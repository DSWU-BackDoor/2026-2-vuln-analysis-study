## Cross-Site Scripting (XSS)

클라이언트 사이드 취약점 중 하나로, 공격자가 웹 리소스에 악성 스크립트를 삽입해 이용자의 웹 브라우저에서 해당 스크립트를 실행할 수 있음. 공격자는 이를 이용해 특정 계정의 세션 정보를 탈취하거나, 해당 계정의 권한으로 임의의 기능을 수행할 수 있음. 보통 이용자가 입력한 내용이 웹 페이지에 출력되는 기능에서 발생함.

| 구분 | 설명 |
| --- | --- |
| **Stored XSS** | XSS에 사용되는 악성 스크립트가 서버에 저장되고, 이후 서버의 응답에 포함되어 전달되는 XSS. 데이터베이스나 파일 등에 저장된 악성 스크립트를 이용자가 조회할 때 발생함. |
| **Reflected XSS** | XSS에 사용되는 악성 스크립트가 URL 등의 요청에 포함되고, 서버가 해당 값을 응답에 그대로 출력하면서 발생하는 XSS. 주로 이용자가 악성 URL에 접속하도록 유도하여 공격함. |
| **DOM-based XSS** | 서버의 응답이 아닌 클라이언트 측에서 JavaScript가 URL Fragment 등의 입력값을 안전하지 않게 처리하면서 발생하는 XSS. |
| **Universal XSS** | 웹 애플리케이션이 아닌 브라우저나 브라우저 플러그인 등의 취약점으로 발생하는 XSS. 이를 통해 일반적인 SOP 정책을 우회할 수 있음. |

### XSS 공격의 원리

XSS는 공격자가 입력한 값이 웹 페이지에서 단순한 문자로 처리되지 않고 HTML이나 JavaScript 코드로 해석될 때 발생함.

```text
공격자가 악성 스크립트 입력
        ↓
웹 애플리케이션이 입력값을 적절하게 처리하지 않음
        ↓
악성 스크립트가 웹 페이지에 포함
        ↓
피해자가 해당 페이지 접근
        ↓
피해자의 브라우저에서 스크립트 실행
```

## Cross-Site Request Forgery (CSRF)

웹 애플리케이션의 요청 위조 취약점 중 하나로, 공격자가 이용자의 의도와 관계없이 이용자의 권한으로 특정 요청을 서버에 전송하도록 유도하는 공격이다.

이용자가 공격 대상 사이트에 로그인한 상태에서 공격자가 만든 페이지나 링크 등을 방문하면, 브라우저에 저장되어 있던 인증 정보가 요청에 함께 포함될 수 있음. 서버에서 해당 요청이 실제 이용자가 의도해서 보낸 것인지 확인하지 않는 경우 공격이 발생할 수 있음.

### CSRF 공격 기법의 원리와 동작 방식

CSRF는 주로 비밀번호 변경, 게시글 작성·삭제, 계정 정보 변경 등 사용자의 상태나 서버의 데이터를 변경하는 기능을 대상으로 발생할 수 있음.

### CSRF 방어 방법

- **CSRF Token**: 서버에서 예측하기 어려운 토큰을 발급하고 정상적인 요청에 함께 포함시킴. 서버에서는 요청에 포함된 토큰이 올바른지 확인하여 위조된 요청인지 판단함.
- **SameSite Cookie**: 쿠키에 `SameSite` 속성을 설정하여 다른 사이트에서 발생한 요청에 인증 쿠키가 전송되는 것을 제한함. `Strict`, `Lax`, `None` 등의 설정이 있음.
- **Origin / Referer 검증**: 요청의 `Origin`이나 `Referer`를 확인하여 신뢰할 수 있는 출처에서 발생한 요청인지 확인함. 허용되지 않은 출처에서 온 요청은 거부할 수 있음.
- **추가 인증**: 비밀번호 변경이나 회원 탈퇴, 결제처럼 중요한 기능을 수행할 때 비밀번호 재입력이나 추가 인증을 요구하여 의도하지 않은 요청이 실행되는 것을 방지할 수 있음.

## XSS와 CSRF 비교

XSS와 CSRF는 모두 웹 애플리케이션에서 발생할 수 있는 공격이지만, **공격하는 방식과 목적에 차이가 있음.**

| 구분      | **XSS**                                   | **CSRF**                                         |
| ------- | ----------------------------------------- | ------------------------------------------------ |
| 공격 원리   | 악성 스크립트를 웹 페이지에 삽입하여 실행                   | 피해자의 브라우저를 이용해 위조된 요청을 서버에 전송                    |
| 주요 대상   | 이용자의 웹 브라우저                           | 이용자의 인증된 세션과 서버 기능**                           |
| 핵심      | 스크립트 실행                               | 요청 위조                                        |
| 공격 방식   | 악성 JavaScript 등이 피해자의 브라우저에서 실행되도록 함      | 피해자가 의도하지 않은 요청을 보내도록 유도                         |
| 필요한 조건  | 사용자 입력이 안전하게 처리되지 않아 스크립트가 실행될 수 있어야 함    | 피해자가 로그인한 상태이고 서버가 요청의 위조 여부를 검증하지 않아야 함         |
| 주요 영향   | 세션 정보 탈취, 페이지 변조, 이용자 권한으로 기능 수행 등        | 비밀번호 변경, 게시글 작성·삭제, 계정 정보 변경 등                   |
| 대표적인 방어 | 입력값 검증, 출력값 인코딩, HTML Sanitization, CSP 등 | CSRF Token, SameSite Cookie, Origin/Referer 검증 등 |

### 핵심적인 차이

> **XSS = 악성 스크립트 실행**
>
> **CSRF = 피해자의 권한으로 요청 위조**

XSS는 공격자가 악성 스크립트를 삽입하여 피해자의 브라우저에서 해당 스크립트를 실행시키는 것이 핵심임. 반면 CSRF는 스크립트 자체를 실행하는 것이 목적이 아니라, 피해자가 로그인한 상태라는 점을 이용해 피해자의 권한으로 원하지 않는 요청을 서버에 보내도록 만드는 것이 핵심임.

두 공격 모두 피해자의 권한을 이용할 수 있지만, XSS는 브라우저에서 악성 코드를 실행시키는 데 초점이 있고, CSRF는 피해자가 의도하지 않은 요청을 서버에 전달하는 데 초점이 있음.
