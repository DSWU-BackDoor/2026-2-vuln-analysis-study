# Out of Bound (OOB)

## 1. Out of Bound(OOB)란?

Out of Bound(OOB)는 배열이나 메모리 영역에 접근할 때, **허용된 범위를 벗어난 위치에 접근하는 취약점**이다.

배열은 선언된 크기만큼의 원소만 접근할 수 있다. 하지만 프로그램에서 인덱스의 유효성을 검사하지 않으면 배열의 범위를 벗어난 메모리에 접근할 수 있다.

예를 들어 크기가 5인 배열의 유효한 인덱스는 0부터 4까지이다. 이때 `arr[5]`와 같이 범위를 벗어난 인덱스에 접근하면 OOB가 발생한다.

## 2. OOB의 종류

OOB는 메모리를 읽는지, 쓰는지에 따라 두 가지로 구분할 수 있다.

### 2.1 Out of Bounds Read

배열의 범위를 벗어난 메모리에서 데이터를 읽는 취약점이다.

범위 밖에 저장된 데이터에 접근할 수 있기 때문에 메모리에 저장된 정보가 노출될 가능성이 있다.

**주요 영향**
- 메모리 내부 정보 유출
- 포인터 및 주소 정보 노출
- 프로그램 내부 데이터 노출

### 2.2 Out of Bounds Write

배열의 범위를 벗어난 메모리 위치에 데이터를 쓰는 취약점이다.

배열 주변에 위치한 다른 메모리 영역의 값이 변경될 수 있으며, 특히 포인터와 같은 중요한 데이터가 변조되면 프로그램의 동작이나 실행 흐름에 영향을 줄 수 있다.

**주요 영향**
- 주변 변수의 값 변조
- 포인터 값 변경
- 프로그램 실행 흐름 변경 가능성

## 3. OOB가 발생하는 원인

OOB는 주로 메모리 접근 과정에서 범위 검증이 제대로 이루어지지 않을 때 발생한다.

대표적인 원인은 다음과 같다.

- **배열 인덱스 검증 부족:** 배열의 크기를 초과하거나 음수인 인덱스에 접근하는 경우
- **잘못된 메모리 크기 계산:** 실제 할당된 메모리보다 큰 범위에 데이터를 읽거나 쓰는 경우
- **사용자 입력값 검증 부족:** 외부에서 입력받은 값을 별도의 검사 없이 배열 인덱스나 메모리 접근에 사용하는 경우

## 4. OOB와 Buffer Overflow의 차이

OOB와 Buffer Overflow는 모두 메모리의 유효한 범위를 벗어나는 문제와 관련이 있지만, 의미에는 차이가 있다.

| 구분 | OOB | Buffer Overflow |
|---|---|---|
| 의미 | 메모리의 유효한 범위를 벗어난 접근 | 버퍼의 크기를 초과하여 데이터가 기록되는 현상 |
| 접근 유형 | 메모리 읽기 및 쓰기 | 주로 메모리 쓰기 |
| 주요 원인 | 인덱스 및 접근 범위 검증 부족 | 버퍼 크기보다 많은 데이터 입력 및 복사 |
| 영향 | 정보 유출, 데이터 변조 등 | 주변 메모리 변조, 실행 흐름 변경 등 |

Buffer Overflow는 OOB Write와 밀접한 관련이 있지만, OOB는 범위를 벗어난 읽기와 쓰기를 모두 포함하는 더 넓은 개념이다.

## 5. OOB의 보안상 위험성

OOB는 단순히 잘못된 메모리에 접근하는 문제에서 끝나지 않고, 공격자가 메모리 정보를 확인하거나 데이터를 변조하는 수단으로 악용될 수 있다.

특히 OOB Write를 통해 포인터와 같이 프로그램의 동작에 중요한 데이터를 변경할 수 있다면 예상하지 못한 메모리 접근이나 실행 흐름 변경으로 이어질 수 있다.

이러한 취약점은 프로그램의 구조와 메모리 배치에 따라 임의 코드 실행과 같은 심각한 보안 문제로 발전할 가능성이 있다.

## 6. OOB 방어 방법

OOB를 방지하기 위해서는 메모리에 접근하기 전에 접근하려는 위치가 유효한 범위에 포함되는지 확인해야 한다.

- **인덱스 범위 검사:** 배열에 접근하기 전 인덱스가 0 이상이고 배열 크기보다 작은지 확인한다.
- **입력값 검증:** 사용자 입력을 배열 인덱스나 메모리 접근에 사용할 경우 허용된 범위인지 검사한다.
- **메모리 크기 확인:** 데이터를 읽거나 복사할 때 실제 할당된 메모리 크기를 초과하지 않도록 제한한다.

## 7. 핵심 정리

- OOB(Out of Bound)는 배열이나 메모리 영역의 유효한 범위를 벗어나 접근하는 취약점이다.
- OOB Read는 범위 밖의 메모리를 읽는 것이고, OOB Write는 범위 밖의 메모리에 데이터를 쓰는 것이다.
- OOB는 정보 유출, 데이터 변조, 프로그램 실행 흐름 변경 등의 보안 문제로 이어질 수 있다.
- 배열 인덱스와 메모리 접근 범위를 검증하는 것이 중요하다.
- 이번 Dreamhack Out of Bound 문제에서는 배열의 범위 검증이 이루어지지 않는 점을 이용해 포인터 값을 조작하고, `system()`의 실행 대상을 변경한다.
