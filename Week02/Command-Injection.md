# Command Injection

## 1. Command Injection의 개념과 위험성

Command Injection은 애플리케이션이 사용자 입력을 운영체제 명령어 실행에 사용하면서 공격자가 의도하지 않은 OS 명령을 실행할 수 있게 되는 취약점이다.

SQL Injection이 SQL 명령어를 대상으로 한다면,

```text
SQL Injection
→ SQL 명령 조작

Command Injection
→ OS 명령 조작
```

으로 구분할 수 있다.

### 위험성

Command Injection이 발생하면 애플리케이션이 실행되는 서버에서 공격자가 의도하지 않은 명령이 실행될 수 있기 때문에 서버의 파일, 프로세스 및 시스템 자원 등에 영향을 줄 수 있다.

## 2. `system()` 함수 사용 시 발생할 수 있는 보안 문제

`system()`과 같이 문자열을 운영체제 명령으로 전달하여 실행하는 함수는 사용자 입력값이 명령어에 포함되는 경우 보안 문제가 발생할 수 있다.

예를 들어 다음과 같이 사용자 입력을 그대로 명령어에 포함시키는 구조는 위험하다.

> > 사용자 입력

    ↓

명령어 문자열에 삽입
↓
system()
↓
OS 명령 실행

특히 사용자 입력에 명령어의 실행 구조를 변경할 수 있는 문자가 포함될 경우, 원래 개발자가 의도한 명령과 다른 명령이 실행될 가능성이 있다.

따라서 `system()`을 사용할 때는 사용자 입력을 직접 명령어 문자열에 결합하지 않는 것이 중요하다.

## 3. 메타 문자 검사 및 안전한 코드 작성 방법

### 메타 문자 검사

Command Injection을 방지하기 위해서는 사용자 입력에 OS 명령어의 의미를 변경할 수 있는 메타 문자가 포함되어 있는지 확인해야 한다.

대표적인 메타 문자:

```text
;
&
|
&&
||
$
`
>
<
```

이러한 문자는 쉘에서 명령어 연결, 리다이렉션, 명령 치환 등의 의미를 가질 수 있다.

따라서 단순히 특정 문자 몇 개를 제거하는 방식보다는 허용할 입력값을 명확하게 정의하는 방식이 안전하다.

### 안전한 코드 작성 방법

#### 1. 사용자 입력을 명령어에 직접 결합하지 않기

위험한 구조:

```text
command = "명령어 " + user_input
system(command)
```

사용자 입력이 명령어의 일부로 직접 해석될 수 있기 때문에 피해야 한다.

#### 2. Allowlist 방식 사용

필요한 입력값의 형식을 미리 정의하고 그 외의 값은 거부한다.

예:

```text
허용:
숫자만 입력

차단:
문자, 공백, 특수문자 등이 포함된 입력
```

#### 3. 가능하면 OS 명령 실행 자체를 사용하지 않기

단순한 파일 처리나 데이터 처리 등을 위해 OS 명령을 사용하는 경우, 해당 기능을 프로그래밍 언어의 API로 대체할 수 있는지 확인한다.

#### 4. 최소 권한 원칙 적용

애플리케이션이 실행되는 계정에 불필요한 관리자 권한을 부여하지 않는다.

Command Injection이 발생하더라도 공격자가 얻을 수 있는 권한과 피해 범위를 줄일 수 있다.

---

## 정리

- Command Injection은 사용자 입력을 통해 OS 명령이 의도하지 않게 실행되는 취약점이다.
- SQL Injection은 SQL을 대상으로 하지만 Command Injection은 운영체제 명령을 대상으로 한다.
- `system()`과 같이 OS 명령을 실행하는 기능에서 사용자 입력을 직접 사용하면 위험할 수 있다.
- 메타 문자는 쉘에서 명령어 연결, 리다이렉션, 명령 치환 등의 의미를 가질 수 있다.
- 사용자 입력을 직접 명령어에 결합하지 않는 것이 중요하다.
- Allowlist 방식으로 입력값을 제한할 수 있다.
- 가능하면 OS 명령 실행 자체를 사용하지 않고 프로그래밍 언어의 API로 대체하는 것이 좋다.
- 최소 권한 원칙을 적용하면 취약점 발생 시 피해 범위를 줄일 수 있다.
