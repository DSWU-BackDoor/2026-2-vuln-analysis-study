# Command Injection (명령어 삽입)

## 1. 개념

**Command Injection**은 애플리케이션이 사용자 입력값을 검증 없이 **운영체제(OS) 명령어**의 일부로 전달할 때 발생하는 취약점이다. 공격자는 입력값에 OS 명령어를 끼워 넣어, 웹 서버의 권한으로 임의의 시스템 명령을 실행할 수 있다.

- **OWASP 분류**: A03:2021 - Injection
- **위험도**: 매우 높음 (서버 원격 제어, 데이터 탈취, 내부망 침투로 이어질 수 있음)

## 2. 발생 원리

웹 애플리케이션이 `system()`, `exec()`, `popen()`, 백틱(`` ` ``) 등 **OS 명령을 실행하는 함수**에 사용자 입력을 그대로 넘길 때 발생한다.

### 취약한 코드 예시 (PHP)

```php
<?php
// 사용자가 입력한 IP로 ping을 실행하는 기능
$ip = $_GET['ip'];
system("ping -c 4 " . $ip);   // 입력값을 그대로 명령어에 연결 → 취약
?>
```

정상 요청:
```
?ip=127.0.0.1
→ 실행: ping -c 4 127.0.0.1
```

공격 요청:
```
?ip=127.0.0.1; cat /etc/passwd
→ 실행: ping -c 4 127.0.0.1; cat /etc/passwd
```

`;` 뒤의 명령까지 함께 실행되어 시스템 계정 정보가 노출된다.

## 3. 주요 명령어 연결 문자 (메타문자)

| 문자 | 의미 | 예시 |
|------|------|------|
| `;` | 앞 명령 종료 후 다음 명령 실행 | `a; whoami` |
| `&&` | 앞 명령 성공 시 다음 실행 | `a && whoami` |
| `\|\|` | 앞 명령 실패 시 다음 실행 | `a \|\| whoami` |
| `\|` | 앞 명령 출력을 다음 명령 입력으로 | `a \| whoami` |
| `` ` ` `` | 명령어 치환 (백틱) | `` `whoami` `` |
| `$(...)` | 명령어 치환 | `$(whoami)` |
| `\n` | 개행으로 명령 구분 | |

## 4. 공격 유형

- **In-band (직접)**: 실행 결과가 응답 화면에 그대로 출력되는 경우
- **Blind (블라인드)**: 결과가 화면에 안 보이는 경우
  - **Time-based**: `sleep 5` 같은 지연 명령으로 응답 시간을 보고 성공 여부 판단
  - **Out-of-band**: `curl`, `nslookup`으로 공격자 서버에 요청을 보내 데이터 유출 확인

## 5. 방어 방법

1. **OS 명령 실행 자체를 피하기** — 가능하면 언어 내장 라이브러리 함수를 사용 (예: 파일 삭제는 `unlink()`, 네트워크 확인은 전용 라이브러리)
2. **입력값 검증 (화이트리스트)** — 허용된 문자/형식만 통과 (IP 입력이면 IP 정규식으로만 검증)
3. **명령어와 인자 분리 실행** — 셸을 거치지 않는 API 사용
   ```python
   # 취약: shell=True + 문자열
   subprocess.run(f"ping -c 4 {ip}", shell=True)
   # 안전: 인자를 리스트로 분리, shell 미사용
   subprocess.run(["ping", "-c", "4", ip])
   ```
4. **메타문자 이스케이프/제거** — `escapeshellarg()`, `escapeshellcmd()` (PHP) 등
5. **최소 권한 원칙** — 웹 서버 프로세스를 낮은 권한으로 실행해 피해 범위 축소

## 6. 핵심 요약

> 사용자 입력이 **OS 명령어로 흘러 들어가는 경로**가 존재하고, 그 입력이 제대로 검증되지 않으면 발생한다. 근본 대책은 "명령어 문자열을 직접 조립하지 않는 것" + "화이트리스트 검증".
