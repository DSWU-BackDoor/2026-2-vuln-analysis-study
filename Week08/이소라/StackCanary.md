# 시스템 취약점 분석 스터디 노트 — Stack Canary (스택 카나리)

> **Stack Smashing Protector (SSP)** 라고도 부른다. Stack Buffer Overflow로 리턴 주소가 덮이는 것을 **실행 중에 탐지**하기 위한 대표적인 완화(Mitigation) 기법이다. 드림핵 `ssp_001` 같은 문제가 이 보호 기법을 다룬다.

---

## 1. 개념

**버퍼와 저장된 리턴 주소 사이에 "랜덤 값(카나리)"을 심어 두고, 함수가 끝나기 직전에 그 값이 바뀌었는지 검사하는 것이다.**

- 카나리(Canary)라는 이름은 **탄광의 카나리**에서 왔다. 광부들이 유독 가스를 먼저 감지하려고 데려간 새처럼, 공격을 **먼저 감지하는 경보** 역할을 한다.
- Stack Buffer Overflow는 버퍼를 넘쳐 **버퍼 → SFP → RET** 순서로 **연속으로** 덮는다. 그 사이에 카나리를 두면, RET를 덮기 전에 반드시 카나리를 먼저 덮게 된다.
- 함수 종료 시 카나리 값이 처음과 다르면, 오버플로가 일어났다고 보고 **프로그램을 즉시 종료**한다 (`__stack_chk_fail` 호출).

> 핵심은 "막는 것이 아니라 **탐지하는 것**"이다. 오버플로 자체를 막지는 못하지만, RET가 쓰이기 전에 알아채서 공격자가 흐름을 탈취하기 전에 죽인다.

---

## 2. 핵심 구조 — 카나리의 위치

카나리는 **지역 변수(버퍼)와 SFP/RET 사이**에 들어간다.

```
높은 주소
┌──────────────────────┐
│ 리턴 주소 (RET)       │  ← 최종 표적
├──────────────────────┤
│ 저장된 EBP/RBP (SFP)  │
├──────────────────────┤
│ 카나리 (Canary)       │  ← 버퍼가 넘치면 RET보다 먼저 덮인다
├──────────────────────┤
│ 지역 변수 buf[...]    │  ← 여기서부터 위로 넘친다
└──────────────────────┘
낮은 주소
```

> 버퍼를 넘쳐 RET까지 가려면 **반드시 카나리를 지나야 한다.** 그래서 공격자가 카나리를 원래 값 그대로 복원하지 못하면 탐지된다.

### 어셈블리에서의 모습 (x86-64 / 리눅스)

카나리는 TLS(Thread Local Storage)의 고정 위치인 **`fs:0x28`** 에 보관된다.

```asm
; 함수 시작 (프롤로그) — 카나리를 스택에 저장
mov    rax, qword ptr fs:[0x28]   ; TLS에서 카나리 원본을 읽어
mov    qword ptr [rbp-0x8], rax   ; 스택(버퍼 위)에 복사해 둔다

; ... 함수 본문 ...

; 함수 종료 (에필로그) — 카나리 검증
mov    rax, qword ptr [rbp-0x8]   ; 스택에 둔 카나리를 읽어
sub    rax, qword ptr fs:[0x28]   ; 원본과 비교(xor/sub)
je     .ok                        ; 같으면 정상 리턴
call   __stack_chk_fail           ; 다르면 *** stack smashing detected *** 후 종료
.ok:
ret
```

> `*** stack smashing detected ***` 메시지를 보면 "카나리가 깨졌다 = 오버플로가 탐지됐다"는 뜻이다.

## 3. 카나리의 종류

| 종류                  | 구성 방식                                                     | 특징                                                                                                                               |
| --------------------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Terminator Canary** | 문자열 종료 문자들로 고정 (`\x00`, `\x0a`, `\xff`, `\x0d` 등) | `strcpy`·`gets` 등 문자열 함수가 종료 문자에서 멈추므로, 공격자가 카나리를 그대로 통과시키기 어렵다. 값이 고정이라 로직은 단순하다 |
| **Random Canary**     | 프로그램 시작 시 `/dev/urandom` 등에서 **무작위 값**을 생성   | 매 실행마다 달라져 미리 알 수 없다. 현재 리눅스 glibc의 기본 방식이다                                                              |
| **Random XOR Canary** | 랜덤 카나리를 제어 데이터(SFP/RET 등)와 **XOR**해서 저장      | 카나리뿐 아니라 제어 데이터가 바뀌어도 검증이 깨진다. 더 강력하다                                                                  |

### 리눅스 카나리의 실제 모습

리눅스 64비트의 랜덤 카나리는 보통 **최하위 1바이트가 `\x00`(널 바이트)** 이다.

```
예: 0x<랜덤 7바이트>00   →   ...a1b2c3d4e5f6 00
```

- 이유: 널 바이트를 맨 앞에 두어 `printf`·`strcpy` 같은 **문자열 함수가 카나리를 통째로 유출·복사하지 못하게** 막는다 (Terminator 성격을 섞은 것이다).
- 부작용: 카나리를 Leak할 때 이 **널 바이트 1개는 고정값**으로 알고 있으므로, 나머지 7바이트만 알아내면 된다.

## 4. 우회 기법 (Bypass)

카나리는 "값을 모르면 못 뚫는다"가 전제다. 그래서 우회는 대부분 **값을 알아내거나(Leak)**, **검사를 건드리지 않고(우회)** 공격하는 방향이다.

### (1) 카나리 유출 (Canary Leak) — 가장 일반적

OOB Read, Format String, 미초기화 메모리 출력 등으로 **스택에 있는 카나리 값을 읽어낸다.** 값을 알아내면, 오버플로 페이로드에 **카나리를 원래 값 그대로 끼워 넣어** 검증을 통과시킨다.

```
[ buf 채우기 ][ 유출한 카나리 값 그대로 ][ SFP ][ RET → 공격 주소 ]
```

- **Format String** (`printf(user_input)`): `%p`, `%lx`를 넣어 스택 값을 줄줄이 출력시켜 카나리를 찾는다.
- **OOB Read**: 범위 밖 읽기로 카나리가 저장된 위치를 읽는다.
- **미초기화 출력**: 입력받은 길이만큼 되돌려주는 로직 등에서 버퍼 뒤 카나리까지 함께 출력될 때 유출된다.

> 리눅스에서는 카나리 최하위 바이트가 `\x00`이라, Leak한 값의 끝이 `00`으로 끝나는지 확인하면 카나리가 맞는지 검증할 수 있다.

### (2) 브루트포스 (Brute Force) — fork 서버 한정

**`fork()`로 자식 프로세스를 만드는 서버**는 부모의 메모리를 그대로 물려받으므로, **카나리 값이 자식마다 동일**하다. 그래서 1바이트씩 맞춰 나갈 수 있다.

- 틀리면 크래시, 맞으면 다음 단계로 넘어가는 반응 차이를 이용한다.
- 64비트 카나리는 널 바이트를 뺀 **7바이트**를 1바이트씩 맞추므로 최대 `256 × 7 = 1792`번이면 된다 (8바이트 전체를 한 번에 맞추는 `256^7`보다 훨씬 적다).
- `execve`로 **새로 실행**되는 서버는 매번 카나리가 바뀌므로 이 방법이 통하지 않는다.

### (3) 카나리를 건너뛰는 공격 (Overwrite 없이 흐름 변조)

카나리를 **아예 덮지 않고** 목표만 조작하는 방법이다. 카나리는 손대지 않았으니 검증을 통과한다.

- **OOB Write / 임의 주소 쓰기**: 인덱스를 조작해 카나리를 건너뛰고 RET나 함수 포인터만 정확히 덮는다. (→ [[out-of-bounds]] 참고)
- **지역 변수·함수 포인터 덮어쓰기**: RET까지 가기 전, 버퍼와 카나리 사이에 있는 다른 변수만 바꿔 로직을 우회한다.

### (4) `__stack_chk_fail` 자체를 노리기

검증 실패 시 호출되는 `__stack_chk_fail`의 **GOT 엔트리를 덮어** 다른 함수로 돌리거나, 출력 흐름을 악용하는 고급 기법도 있다 (Partial RELRO 환경 등).

### (5) 카나리를 거치지 않는 취약점 이용

- **SFP 1바이트만 바꾸는 Off-by-One** 등 카나리 아래쪽만 건드리는 경우.
- 애초에 카나리로 보호되지 않는 함수(버퍼가 없다고 판단된 함수)의 취약점을 노리는 경우.

## 5. ssp_001 류 문제에 적용하기

드림핵 `ssp_001` 같은 문제는 보통 다음 조합으로 풀린다.

1. **카나리 확인**: `checksec`으로 `Canary found`를 확인한다. 보호가 켜져 있으니 단순 BOF로는 RET를 못 덮는다.
2. **Leak 수단 찾기**: 입력받은 값을 되돌려 출력하는 함수, 배열 인덱스로 스택을 읽는 기능 등 **카나리를 읽을 통로**를 찾는다. (ssp_001은 음수/특정 인덱스로 스택의 카나리 바이트를 읽는 패턴이 흔하다.)
3. **카나리 복원**: 유출한 바이트로 8바이트 카나리를 조립한다 (최하위 바이트 `\x00` 확인).
4. **페이로드 구성**: `[버퍼][카나리 그대로][SFP][RET → get_shell/원하는 주소]` 순으로 쌓는다.
5. **익스플로잇**: 카나리가 일치하므로 검증을 통과하고, RET가 목표 주소로 넘어간다.

> 정리하면 ssp_001의 핵심은 **"카나리를 먼저 Leak → 그대로 끼워 넣어 검증 통과 → RET 덮기"** 흐름이다.

## 6. 꼭 알아야 할 포인트

- **카나리는 버퍼와 SFP/RET 사이에 위치한다.** → ⭐ 출제 포인트: "카나리는 어디에 있는가?"
- **카나리는 공격을 막는 게 아니라 탐지한다.** 오버플로는 이미 일어났지만, RET가 쓰이기 전에 죽여서 흐름 탈취를 차단한다.
- **리눅스 64비트 카나리의 최하위 바이트는 `\x00`이다.** 문자열 함수의 유출·복사를 막기 위함이며, Leak 시엔 이 1바이트가 고정이라 7바이트만 알면 된다.
- **TLS의 `fs:0x28`에 원본이 보관된다.** 프롤로그에서 스택에 복사하고, 에필로그에서 비교한다.
- **카나리로 못 막는 공격을 구분한다.** → ⭐ 출제 포인트

| 공격 유형                    | 카나리로 막히는가?                         |
| ---------------------------- | ------------------------------------------ |
| 연속 BOF로 RET 덮기          | **막힌다** (카나리가 먼저 깨진다)          |
| 카나리 Leak 후 BOF           | 못 막는다 (값을 복원해 통과시킨다)         |
| OOB Write (카나리 건너뛰기)  | 못 막는다 (카나리를 건드리지 않는다)       |
| 지역 변수·함수 포인터만 덮기 | 못 막는다 (RET까지 안 가도 된다)           |
| fork 서버 브루트포스         | 못 막는다 (값이 고정이라 1바이트씩 맞춘다) |

- **다른 보호 기법과의 관계.** 카나리는 **Stack Overflow 탐지** 전용이다. NX(코드 실행 차단), ASLR/PIE(주소 무작위화), RELRO(GOT 보호)와 역할이 다르며, 실제로는 여러 개를 겹쳐 쓴다 (Defense in Depth). (→ [[stack-buffer-overflow]]의 보호 기법 표 참고)

## 7. 방어 관점 (개발자 입장)

1. **컴파일러 옵션을 켠다.** GCC는 기본적으로 카나리를 넣지만, 수준을 명시하는 것이 좋다.
   ```bash
   gcc -fstack-protector-strong app.c     # 권장: 버퍼·주소 노출 함수에 폭넓게 적용
   # -fstack-protector        : 제한적 적용 (char 배열 ≥ 8바이트 등)
   # -fstack-protector-all    : 모든 함수에 적용 (성능 비용 큼)
   # -fno-stack-protector     : 끄기 (워게임·분석용, 실제 배포 금지)
   ```
2. **카나리는 "최후의 경보"일 뿐이다.** 근본 원인인 Buffer Overflow·OOB를 애초에 막아야 한다. 입력 길이 검증, 안전한 함수 사용, 경계 검사를 함께 적용한다.
3. **Leak 경로를 차단한다.** Format String 취약점 제거(`printf("%s", user)`), 미초기화 메모리 출력 방지로 카나리가 새지 않게 한다.
4. **다른 보호 기법과 병행한다.** NX, ASLR/PIE, Full RELRO, 그리고 **Shadow Stack(Intel CET)** 같은 하드웨어 리턴 주소 보호를 함께 켠다.
5. **메모리 안전 언어를 검토한다.** Rust·Go 등은 경계 검사를 기본 제공하므로 카나리에 의존할 상황 자체를 줄인다.
