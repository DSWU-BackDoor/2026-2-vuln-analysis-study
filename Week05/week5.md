# Stack Buffer Overflow

## 1. Stack Buffer Overflow란?

Stack Buffer Overflow는 스택(Stack)에 할당된 버퍼의 크기보다 많은 데이터를 입력하여 인접한 메모리 영역까지 덮어쓰는 취약점이다.

버퍼는 프로그램이 데이터를 임시로 저장하기 위해 사용하는 메모리 공간이다. 입력값의 길이를 제대로 제한하지 않으면 버퍼의 범위를 초과하는 데이터가 기록될 수 있다.

## 2. 발생 원리

함수가 실행되면 지역 변수와 함수 호출에 필요한 정보 등이 스택에 저장될 수 있다.

다음 코드는 버퍼 오버플로우가 발생할 수 있는 예시이다.

```c
#include <stdio.h>

int main(void) {
    char buf[8];

    scanf("%s", buf);
    printf("%s\n", buf);

    return 0;
}
```

`buf`는 8바이트 크기의 배열이다. 하지만 `scanf("%s", buf)`는 입력 길이를 제한하지 않으므로, 8바이트를 초과하는 입력이 들어오면 버퍼의 범위를 벗어나 데이터가 기록될 수 있다.

문자열의 끝에는 널 종료 문자(`\0`)가 필요하므로, 8바이트 배열에 안전하게 저장할 수 있는 문자열은 최대 7바이트이다.

## 3. 취약점 발생 흐름

```text
사용자 입력
    ↓
스택 버퍼에 데이터 저장
    ↓
버퍼 크기를 초과한 입력
    ↓
인접한 메모리 영역 덮어쓰기
    ↓
프로그램 오작동 또는 실행 흐름 변조 가능
```

버퍼 오버플로우가 발생하면 인접한 지역 변수의 값이 변경되거나, 상황에 따라 저장된 프레임 포인터 및 반환 주소가 손상될 수 있다.

공격자는 이러한 특성을 이용해 프로그램의 동작을 변경할 수 있다. 다만 실제로 어떤 메모리가 덮어써지는지는 변수 배치와 컴파일 환경 등에 따라 달라진다.

## 4. 주요 대응 방법

- **입력 길이 제한:** 버퍼의 크기를 초과하는 입력이 들어오지 않도록 제한한다.
- **안전한 입력 처리:** `fgets()`처럼 버퍼 크기를 지정할 수 있는 함수를 사용하고, 반환값과 입력 길이를 검사한다.
- **Stack Canary:** 스택의 특정 값이 변조되었는지 검사하여 일부 버퍼 오버플로우를 탐지한다.
- **NX 및 ASLR:** 메모리에서의 코드 직접 실행을 제한하거나 주소를 무작위화하여 공격을 어렵게 만든다.

보호 기법은 공격을 어렵게 만드는 수단이며, 근본적으로는 올바른 입력 검증과 메모리 관리가 중요하다.

## 5. Dreamhack bof 문제와의 연결

Dreamhack의 [bof 문제](https://dreamhack.io/wargame/challenges/1111)에서는 GDB를 이용해 입력 버퍼와 파일 경로 변수의 메모리 위치를 분석하였다.

입력 형식은 `%144s`였으며, 입력 버퍼와 파일 경로 변수의 시작 주소 사이에는 128바이트의 간격이 있었다. 이를 통해 버퍼의 범위를 초과하는 입력이 파일 경로 변수까지 덮어쓸 수 있음을 확인하였다.

이 문제에서는 반환 주소를 덮어쓰는 대신 파일 경로를 변경하여 `read_cat()` 함수가 다른 파일을 읽도록 만들었다.

이를 통해 Stack Buffer Overflow는 반환 주소뿐 아니라 인접한 변수의 값을 변경하여 프로그램의 동작에도 영향을 줄 수 있다는 점을 이해하였다.

## 6. 정리

Stack Buffer Overflow는 스택 버퍼의 크기보다 많은 데이터를 기록할 때 발생하는 메모리 취약점이다. 입력 길이를 적절히 제한하지 않으면 인접한 메모리 영역이 손상될 수 있으며, 상황에 따라 프로그램의 실행 흐름까지 변조될 수 있다.

이번 학습을 통해 버퍼 크기와 입력 길이의 관계, 스택 메모리 구조, 그리고 GDB를 이용한 취약점 분석의 기본 원리를 이해하였다.
