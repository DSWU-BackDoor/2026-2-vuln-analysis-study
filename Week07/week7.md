# Shellcode

## 1. Shellcode란?

Shellcode는 공격자가 원하는 동작을 수행하도록 작성한 기계어 코드이다.

일반적으로 취약점을 이용해 프로그램의 실행 흐름을 변경하고, 공격자가 준비한 코드를 실행시키는 데 사용된다.

초기에는 시스템 명령어 셸을 실행하는 코드가 주로 사용되어 Shellcode라는 이름이 붙었지만, 현재는 다양한 기능을 수행하는 공격 코드를 의미한다.

## 2. Shellcode의 실행 원리

Shellcode는 메모리에 저장된 기계어 명령어이므로, CPU가 해당 메모리 영역을 실행하도록 해야 한다.

일반적인 실행 과정은 다음과 같다.

1. 공격자가 Shellcode를 입력한다.
2. 입력한 코드가 메모리 영역에 저장된다.
3. 취약점을 이용해 프로그램의 실행 흐름을 Shellcode가 저장된 주소로 변경한다.
4. CPU가 해당 주소부터 명령어를 실행한다.

## 3. Shellcode의 주요 특징

Shellcode를 작성할 때는 프로그램의 실행 환경과 메모리 구조를 고려해야 한다.

- **아키텍처:** 32비트와 64비트 환경에 따라 명령어와 시스템 콜 사용 방식이 다르다.
- **기계어:** Shellcode는 CPU가 직접 실행할 수 있는 기계어 바이트로 구성된다.
- **시스템 콜:** 운영체제의 기능을 사용하기 위해 시스템 콜을 호출할 수 있다.
- **메모리 권한:** Shellcode가 저장된 메모리 영역에 실행 권한이 필요하다.
- **Bad Character:** 프로그램에서 특정 바이트를 차단하는 경우 해당 바이트를 포함하지 않도록 작성해야 한다.

## 4. Shellcode와 System Call

System Call(시스템 콜)은 프로그램이 운영체제 커널의 기능을 사용하기 위해 요청하는 방법이다.

Shellcode는 시스템 콜을 이용해 파일 읽기, 프로세스 실행, 네트워크 통신 등의 작업을 수행할 수 있다.

리눅스 x86-64 환경에서는 `syscall` 명령어를 사용하며, 주요 레지스터의 역할은 다음과 같다.

| 레지스터 | 역할 |
|---|---|
| `rax` | 시스템 콜 번호 |
| `rdi` | 첫 번째 인자 |
| `rsi` | 두 번째 인자 |
| `rdx` | 세 번째 인자 |
| `r10` | 네 번째 인자 |
| `r8` | 다섯 번째 인자 |
| `r9` | 여섯 번째 인자 |

## 5. Shellcode 작성 시 고려해야 할 요소

Shellcode는 일반적인 프로그램 코드와 달리 메모리에 직접 배치되어 실행되므로 몇 가지 요소를 고려해야 한다.

- **Null Byte:** `0x00`은 문자열의 종료 문자로 사용되기 때문에 입력 처리 과정에서 Shellcode가 중간에 잘릴 수 있다.
- **Bad Character:** 프로그램에서 특정 바이트를 차단하는 경우 해당 바이트가 포함되지 않도록 작성해야 한다.
- **엔디안(Endianness):** 메모리에 데이터가 저장되는 바이트 순서를 고려해야 한다.
- **인코딩(Encoding):** 금지된 바이트가 포함된 경우 데이터를 다른 형태로 변환하고, 실행 전에 원래 코드로 복원하는 방법을 사용할 수 있다.

## 6. Shellcode와 메모리 보호 기법

Shellcode가 실행되려면 코드가 저장된 메모리 영역에 실행 권한이 있어야 한다.

대표적인 메모리 보호 기법은 다음과 같다.

- **NX(No-eXecute):** 스택이나 힙과 같은 메모리 영역에서 코드가 실행되는 것을 제한하는 기법이다.
- **ASLR(Address Space Layout Randomization):** 메모리 영역의 주소를 무작위로 배치하여 공격자가 특정 주소를 예측하기 어렵게 만드는 기법이다.
- **PIE(Position Independent Executable):** 실행 파일의 코드 영역도 메모리에서 무작위 주소에 배치될 수 있도록 하는 기법이다.

다만 프로그램이 `mmap()` 등을 이용해 실행 권한이 있는 메모리 영역을 직접 생성한다면, NX가 활성화된 환경에서도 해당 메모리 영역에서 코드가 실행될 수 있다.

## 7. Shellcode의 보안상 위험성

Shellcode는 프로그램의 실행 흐름을 공격자가 원하는 방향으로 변경할 수 있다는 점에서 위험하다.

취약점을 통해 Shellcode가 실행되면 공격자는 시스템 명령어 실행, 파일 접근, 정보 유출 등의 동작을 수행할 수 있다.

특히 메모리 보호 기법이 적용되지 않았거나 이를 우회할 수 있는 환경에서는 임의 코드 실행으로 이어질 가능성이 있다.

## 8. Shellcode 방어 방법

Shellcode 실행을 방지하기 위해서는 메모리 보호 기법을 적용하고, 취약점이 발생하지 않도록 프로그램을 작성해야 한다.

- **NX 적용:** 데이터 영역에서 임의의 코드가 실행되지 않도록 제한한다.
- **ASLR 및 PIE 적용:** 메모리 주소를 예측하기 어렵게 만든다.
- **입력값 검증:** 외부에서 전달되는 입력값의 크기와 형식을 검사한다.
- **메모리 접근 검증:** 잘못된 메모리 접근이나 실행 흐름 변경이 발생하지 않도록 한다.
- **보안 컴파일 옵션 적용:** Canary, RELRO 등 다양한 보호 기법을 함께 사용한다.

## 9. 핵심 정리

- Shellcode는 공격자가 원하는 동작을 수행하도록 작성한 기계어 코드이다.
- 취약점을 이용해 프로그램의 실행 흐름을 변경하고 Shellcode를 실행할 수 있다.
- System Call을 이용하면 운영체제의 기능을 사용할 수 있다.
- Shellcode 작성 시 Null Byte, Bad Character, 엔디안, 메모리 권한 등을 고려해야 한다.
- NX, ASLR, PIE 등의 메모리 보호 기법은 Shellcode를 이용한 공격을 어렵게 만든다.
- 프로그램이 실행 권한이 있는 메모리 영역을 직접 생성하는 경우 NX가 활성화되어 있어도 해당 영역에서 Shellcode가 실행될 수 있다.
